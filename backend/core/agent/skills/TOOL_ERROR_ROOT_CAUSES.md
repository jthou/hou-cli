# 工具调用错误的根本原因分析

## 核心问题

### 1. 代码字符串被错误地当作表达式求值 ✅ 已修复

**根本原因**:
- `_resolve_inputs` 方法对所有字符串参数都调用 `_evaluate_expression`
- 代码字符串（多行 Python 代码）不应该被当作表达式求值
- 代码中的字符串字面量（如 `' '.join`）被错误地当作变量引用处理

**修复方案**:
- 对于 `code` 参数，只替换变量引用（`${input.}`, `${steps[}`, `${config.}`），不进行表达式求值
- 检测代码中使用的引号类型，正确转义字符串中的特殊字符

### 2. 表达式求值返回 `None` ✅ 已修复

**根本原因**:
- `ExpressionEvaluator.evaluate()` 在表达式求值失败时返回 `None`
- 如果 `code` 参数的表达式求值返回 `None`，会导致 `code` 参数为 `None`
- 工具执行时检查 `if not code:` 会触发 "Code parameter is required" 错误

**修复方案**:
- 在 `_resolve_inputs` 中，如果表达式求值返回 `None`，保留原始值
- 添加 `code` 参数验证，在执行工具前检查参数是否有效

### 3. 变量引用不存在时被替换为空字符串 ✅ 已修复

**根本原因**:
- 如果 `steps[2].subtitle_path` 不存在，`_get_steps_value` 返回 `None`
- 代码字符串中的变量引用被替换为空字符串 `""`
- 导致代码字符串变成 `subtitle_path = ""`，可能引发运行时错误

**修复方案**:
- 如果变量不存在，保留原始变量引用 `${steps[2].subtitle_path}`，而不是替换为空字符串
- 这样可以避免代码执行时的错误，让错误信息更清晰

### 4. 代码字符串替换后为空 ✅ 已修复

**根本原因**:
- 如果代码字符串中的所有变量引用都被替换为空字符串，可能导致代码字符串为空
- 空的代码字符串会导致工具执行失败

**修复方案**:
- 添加验证，如果替换后的代码为空，保留原始代码
- 记录详细的调试日志

## 其他潜在问题

### 5. 表达式求值返回非字符串类型 ⚠️ 需要处理

**问题**:
- `_evaluate_expression` 可能返回非字符串类型（如 `bool`, `int`, `None`）
- 如果工具期望字符串参数，但收到了其他类型，可能导致类型错误

**影响**:
- 工具参数验证可能失败
- 工具执行时可能出现类型错误

**建议修复**:
- 在 `_resolve_inputs` 中，根据工具参数的类型定义，进行适当的类型转换
- 或者，在工具执行前，根据工具的参数定义进行类型转换

### 6. 工具参数验证失败 ⚠️ 需要处理

**问题**:
- 工具参数验证可能失败（参数类型不匹配、必需参数缺失、枚举值不匹配等）
- 表达式求值返回的类型可能与工具期望的类型不匹配

**影响**:
- 工具执行被拒绝
- 错误信息可能不够清晰

**建议修复**:
- 在 `_resolve_inputs` 后，添加参数验证和类型转换
- 如果参数验证失败，提供更详细的错误信息，包括期望的类型和实际收到的类型

### 7. 步骤索引错误 ⚠️ 需要处理

**问题**:
- 如果前面的步骤被跳过，步骤索引可能不连续
- 代码字符串中的 `steps[2].subtitle_path` 可能引用不存在的步骤

**影响**:
- 变量引用失败，导致代码字符串无效

**建议修复**:
- 在替换变量引用时，检查步骤是否存在
- 如果步骤不存在，保留原始变量引用，或抛出明确的错误
- 改进步骤索引的计算逻辑，确保索引的连续性

### 8. 路径提取不完整 ⚠️ 已使用 PathExtractor，但需要验证

**问题**:
- 虽然已经使用 `PathExtractor`，但如果路径提取失败，`video_path` 可能不完整
- 不完整的路径可能导致后续步骤失败

**影响**:
- 文件操作失败
- 工具执行失败

**建议修复**:
- 添加路径验证，确保提取的路径是完整的
- 如果路径提取失败，提供明确的错误信息

### 9. 代码字符串中的引号检测失败 ⚠️ 已处理，但可能需要改进

**问题**:
- 如果代码字符串中的变量引用前后没有引号，无法检测引号类型
- 默认使用双引号，但如果代码中使用的是单引号，可能导致转义错误

**影响**:
- 字符串转义错误，导致代码执行失败

**建议修复**:
- 改进引号检测逻辑，支持更多场景
- 如果无法检测引号类型，使用更安全的转义方式

## 根本原因总结

**核心问题**: 代码字符串和表达式字符串的处理逻辑混淆

1. **代码字符串**（如 `code_executor` 工具的 `code` 参数）:
   - 应该只替换变量引用，不进行表达式求值
   - 应该保留代码结构，不改变代码的语法

2. **表达式字符串**（如条件表达式、参数值）:
   - 应该进行表达式求值
   - 应该返回求值后的结果

**解决方案**: 在 `_resolve_inputs` 中区分代码字符串和表达式字符串，对它们采用不同的处理策略。
