# 技能匹配逻辑文档

## 概述

技能匹配系统根据用户输入自动选择最合适的技能。匹配过程基于关键词、文件路径、URL 等多种因素，使用分数机制进行排序。

## 匹配流程

### 1. 输入预处理
- 将用户输入转换为小写（大小写不敏感）
- 检测是否为本地文件路径
- 检测是否为 URL

### 2. 分数计算

每个技能都会计算一个匹配分数，分数越高表示匹配度越高。

#### 2.1 精确名称匹配（最高优先级）
- **分数**: +1000
- **条件**: 技能名称出现在用户输入中
- **特点**: 一旦匹配，直接返回，不再考虑其他因素

#### 2.2 关键词匹配

系统检测用户输入和技能描述中的关键词：

**关键词类别**:
- `download_keywords`: ["下载", "download", "下", "获取视频"]
- `summary_keywords`: ["摘要", "总结", "summary", "分析", "analyze", "阅读", "read"]
- `video_keywords`: ["视频", "video", "bilibili", "b站", "哔哩"]
- `audio_keywords`: ["音频", "audio", "分离", "提取"]
- `subtitle_keywords`: ["字幕", "subtitle", "srt", "转成", "转"]
- `ffmpeg_keywords`: ["ffmpeg"]
- `whisper_keywords`: ["whisper"]
- `cut_keywords`: ["剪辑", "cut", "trim", "slice", "裁剪", "截取", "提取片段", "片段"]
- `merge_keywords`: ["合并", "merge", "拼接", "连接"]
- `edit_keywords`: ["编辑", "edit", "处理"]

**匹配规则**:
- 如果用户输入包含关键词 A，且技能描述也包含关键词 A，则加分
- 不同关键词组合有不同的加分规则

#### 2.3 本地文件路径特殊处理

**检测模式**:
- `^[~/]`: 以 ~ 或 / 开头
- `\.mp4\b`, `\.avi\b`, `\.mkv\b`, `\.mov\b`: 视频文件扩展名
- `^[a-z]:\\`: Windows 路径
- `/home/`, `/Users/`: Linux/macOS 路径

**匹配规则**:
- 如果检测到本地文件路径，根据用户意图匹配：
  - **剪辑操作** (+1200): 如果包含剪辑关键词或时间范围，优先匹配 `video_cut`
  - **合并操作** (+1200): 如果包含合并关键词，优先匹配 `video_merge`
  - **字幕操作** (+1000): 如果包含字幕/ffmpeg/whisper 关键词，优先匹配 `video_extract_srt`
  - **默认** (+600): 默认匹配 `video_extract_srt`
  - **负分**: `video_downloader` 不处理本地文件，给予 -500 分

#### 2.4 URL 特殊处理

**检测模式**:
- `https?://`: HTTP/HTTPS URL
- `www\.`: www. 开头
- `bilibili\.com`, `youtube\.com`: 视频网站域名

**匹配规则**:
- `video_downloader`: +300
- `video_extract_srt`: +200（如果包含字幕关键词，额外 +300）

#### 2.5 操作类型匹配

**下载操作** (+500):
- 条件: 用户只要求下载，不要求摘要或字幕，且不是本地文件
- 匹配: 专门的下载技能（如 `video_downloader`）

**字幕提取** (+600):
- 条件: 用户要求字幕提取，不要求摘要
- 匹配: `video_extract_srt`

**摘要/分析** (+300):
- 条件: 用户要求摘要或分析
- 匹配: 摘要技能

**音频提取** (+400):
- 条件: 用户要求音频提取/ffmpeg/whisper，不要求摘要
- 匹配: `video_extract_srt`

**剪辑操作** (+800):
- 条件: 用户要求剪辑或提供时间范围
- 匹配: `video_cut`

**合并操作** (+800):
- 条件: 用户要求合并
- 匹配: `video_merge`

**通用视频关键词** (+50):
- 条件: 用户输入和技能描述都包含视频关键词

#### 2.6 优先级加分

**规则**: 只有在已有匹配分数（score > 0）时才给优先级加分，避免误匹配

- **P0 优先级**: +100
- **P1 优先级**: +50
- **P2 优先级**: 不加分

#### 2.7 最低匹配阈值

- **阈值**: 50 分
- **规则**: 只有分数 >= 50 的技能才会被考虑
- **目的**: 避免完全无关的技能被匹配

### 3. 结果选择

1. 收集所有分数 >= 50 的技能
2. 按分数降序排序
3. 返回分数最高的技能
4. 如果没有匹配的技能，返回 `None`

## 匹配示例

### 示例 1: 精确名称匹配
```
输入: "请使用 video_downloader 下载视频"
匹配: video_downloader (分数: 1000)
```

### 示例 2: 关键词匹配
```
输入: "下载这个视频"
匹配: video_downloader (分数: 500 + 100 = 600)
```

### 示例 3: URL 匹配
```
输入: "https://www.bilibili.com/video/BV123456"
匹配: video_downloader (分数: 300 + 100 = 400)
```

### 示例 4: 本地文件 + 剪辑
```
输入: "/home/user/video.mp4 剪辑 00:05:00 到 00:10:00"
匹配: video_cut (分数: 1200)
```

### 示例 5: 误匹配防护
```
输入: "查北京的天气"
匹配: None (分数: 0 < 50，不匹配)
```

## 最佳实践

### 1. 技能描述
- 在技能描述中包含清晰的关键词
- 使用中英文关键词，提高匹配准确度

### 2. 优先级设置
- **P0**: 最常用、最重要的技能（如 `video_downloader`）
- **P1**: 一般技能
- **P2**: 较少使用的技能

### 3. 关键词选择
- 使用常见的中英文关键词
- 避免过于宽泛的关键词（如"处理"、"操作"）

### 4. 测试覆盖
- 测试精确匹配
- 测试关键词匹配
- 测试误匹配防护
- 测试边界情况

## 常见问题

### Q: 为什么我的技能没有被匹配到？
A: 检查以下几点：
1. 技能是否已注册
2. 用户输入是否包含相关关键词
3. 匹配分数是否 >= 50
4. 是否有其他技能分数更高

### Q: 为什么完全不相关的技能被匹配了？
A: 这可能是优先级加分导致的误匹配。确保：
1. 优先级加分只在有相关匹配时才生效（已修复）
2. 最低匹配阈值设置为 50
3. 技能描述中的关键词要准确

### Q: 如何调试技能匹配？
A: 查看日志输出：
```
INFO [backend.core.agent.skills.registry] 技能匹配: '用户输入' -> skill_name (分数: 100)
```
