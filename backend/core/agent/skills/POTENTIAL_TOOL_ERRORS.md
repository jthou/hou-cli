# 可能导致工具调用出错的问题分析

## 已修复的问题

1. ✅ **`code` 参数被错误地进行表达式求值**
   - **问题**: `_resolve_inputs` 对所有字符串都调用 `_evaluate_expression`，导致代码字符串被当作表达式求值
   - **影响**: 代码字符串中的 `' '.join` 被错误替换，导致语法错误
   - **修复**: 对于 `code` 参数，只替换变量引用，不进行表达式求值

2. ✅ **`ExpressionEvaluator.evaluate()` 返回 `None` 的处理**
   - **问题**: 如果表达式求值失败，返回 `None`，导致 `code` 参数为 `None`
   - **影响**: 触发 "Code parameter is required" 错误
   - **修复**: 在 `_resolve_inputs` 中，如果表达式求值返回 `None`，保留原始值

3. ✅ **变量引用不存在时返回空字符串**
   - **问题**: 如果变量不存在，返回空字符串，导致代码字符串无效
   - **影响**: 代码执行时可能出错
   - **修复**: 如果变量不存在，保留原始变量引用，而不是替换为空字符串

4. ✅ **代码字符串替换后为空的验证**
   - **问题**: 如果代码字符串替换后为空，可能导致工具执行失败
   - **影响**: 工具执行时参数无效
   - **修复**: 添加验证，如果替换后的代码为空，保留原始代码

5. ✅ **`code` 参数验证**
   - **问题**: 如果 `code` 参数为 `None` 或空字符串，工具执行会失败
   - **影响**: 触发 "Code parameter is required" 错误
   - **修复**: 在执行工具前，验证 `code` 参数是否有效

## 潜在问题分析

### 1. `ExpressionEvaluator.evaluate()` 返回 `None`

**位置**: `backend/core/agent/utils/expression_utils.py:85`

**问题**:
- 如果表达式求值失败，`evaluate()` 返回 `None`
- 如果 `code` 参数的表达式求值返回 `None`，会导致 `code` 参数为 `None`，触发 "Code parameter is required" 错误

**触发场景**:
- 表达式语法错误
- 变量引用不存在
- 表达式求值异常

**修复建议**:
- 在 `_resolve_inputs` 中，如果 `code` 参数的表达式求值返回 `None`，应该保留原始代码字符串
- 或者在 `ExpressionEvaluator.evaluate()` 中，对于代码字符串，不应该返回 `None`，而应该返回原始表达式

### 2. 变量引用不存在时返回空字符串

**位置**: `backend/core/agent/skills/executor.py:757`

**问题**:
- 如果 `steps[2].subtitle_path` 不存在，`actual_value` 为 `None`，返回空字符串 `""`
- 这会导致代码字符串变成 `subtitle_path = ""`，可能导致运行时错误

**触发场景**:
- 步骤2 `generate_subtitle` 被跳过，`steps[2]` 不存在或没有 `subtitle_path` 字段
- 步骤索引错误

**修复建议**:
- 如果变量不存在，应该保留原始变量引用 `${steps[2].subtitle_path}`，而不是替换为空字符串
- 或者在替换时添加错误处理，如果变量不存在，抛出明确的错误

### 3. 表达式求值返回非字符串类型

**位置**: `backend/core/agent/skills/executor.py:801`

**问题**:
- `_evaluate_expression` 可能返回非字符串类型（如 `bool`, `int`, `None`）
- 如果工具期望字符串参数，但收到了其他类型，可能导致类型错误

**触发场景**:
- 条件表达式返回布尔值
- 数字表达式返回整数或浮点数
- 表达式求值失败返回 `None`

**修复建议**:
- 在 `_resolve_inputs` 中，对于非 `code` 参数，如果表达式求值返回非字符串类型，应该转换为字符串
- 或者根据工具参数的类型定义，进行适当的类型转换

### 4. 代码字符串中的引号检测失败

**位置**: `backend/core/agent/skills/executor.py:759-770`

**问题**:
- 如果代码字符串中的变量引用前后没有引号，无法检测引号类型
- 默认使用双引号，但如果代码中使用的是单引号，可能导致转义错误

**触发场景**:
- 代码字符串格式不规范
- 变量引用不在引号内（如 `path = ${steps[0].video_path}`）

**修复建议**:
- 改进引号检测逻辑，支持更多场景
- 如果无法检测引号类型，使用更安全的转义方式（如使用 `repr()` 然后移除外层引号）

### 5. 工具参数验证失败

**位置**: `backend/core/agent/tools/base.py:65-92`

**问题**:
- 工具参数验证可能失败，导致工具执行被拒绝
- 参数类型不匹配、必需参数缺失、枚举值不匹配等

**触发场景**:
- 表达式求值返回的类型与工具期望的类型不匹配
- 必需参数在表达式求值后变成 `None` 或空字符串

**修复建议**:
- 在 `_resolve_inputs` 后，添加参数验证和类型转换
- 如果参数验证失败，提供更详细的错误信息

### 6. 路径提取不完整

**位置**: `backend/core/agent/orchestrator.py:_extract_skill_parameters`

**问题**:
- 虽然已经使用 `PathExtractor`，但如果路径提取失败，`video_path` 可能不完整
- 不完整的路径可能导致后续步骤失败

**触发场景**:
- 文件名包含特殊字符
- 多个文件路径格式不一致
- 目录路径提取失败

**修复建议**:
- 添加路径验证，确保提取的路径是完整的
- 如果路径提取失败，提供明确的错误信息

### 7. 步骤索引错误

**位置**: `backend/core/agent/skills/executor.py:744`

**问题**:
- 如果 `steps[2]` 不存在，`_get_steps_value` 返回 `None`
- 代码字符串中的变量引用被替换为空字符串或 `None`

**触发场景**:
- 前面的步骤被跳过，导致步骤索引不连续
- 步骤索引计算错误

**修复建议**:
- 在替换变量引用时，检查变量是否存在
- 如果变量不存在，保留原始变量引用，或抛出明确的错误

   - 对于代码字符串，不应该返回 `None`，而应该返回原始表达式

   - 记录变量替换前后的代码字符串
   - 记录表达式求值的结果
   - 记录工具参数验证的详细信息
