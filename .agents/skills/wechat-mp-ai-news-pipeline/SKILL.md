# 微信公众号 × AI 热点：主编编排管道

## 读者收获宪法（最高优先级，违者整段删）

写任何一段前，先能回答下面两句；**答不上来就删段，不要凑字**。

1. **读者多知道什么**：读完这一段，能否用**自己的话**向同事转述**一件具体事**（谁、做了什么、数字或版本、何时）？
2. **与上一段的信息差**：这一段是否提供了**新事实或新关系**，而不是换一种说法重复「要重视、要体系化、要安全」？

**禁止「正确的废话」**（形似洞察、实为空心）：

- 只有情绪或方向词、没有主体：**产业情绪回归理性**、**业界跨越概念炒作**、**转向系统化落地**——除非同句或紧邻一句给出**可核对主体**（公司/产品/政策名 + 时间 + 出处）。
- 只有「强调」「警告」「探索」而无动作对象：**云服务商与安全架构师强调…**——必须写成**谁**对**哪类客户**在**哪份文档或访谈**里说了**哪条可操作要求**（并附链接或报道名）。
- 学术名词当结论卖：**GraphRAG / Agentic RAG 缓解了…但研究指出缺乏评测…**——除非交代**哪篇/哪组实验**、**什么指标**、**与生产落地的差距具体在哪一环**；否则不写这类「综述腔」单段。

**人类语言 vs AI 腔**：人类读完要的是**可带走的认知增量**（一条能转述的事实、一个能执行的判断、一个能点开的出处）；不是**通篇正确的结论**叠在一起却**没有任何一条能复述给第三人听**。

**事实与结论纪律（全阶段）**：

- **言之有物**：每段以**可核对信息**为主（主体、行为、时间、数据、条款、产品版本等至少其一）；避免「很大」「很强」「深刻变化」等**可换成任何行业都成立**的空话。
- **无据不结论**：凡判断句（「将」「必然」「已经」「本质是」），须在**同段或邻段**给出素材中的**出处**（链接、报道名、文档名）；素材没有则写**「检索未覆盖 / 尚不可核」**或删句，**禁止**用常识或模型内推补全。
- **禁臆断、禁妄断**：不写「显然」「毫无疑问」「背后真正的原因是」等**无引用的因果与动机**；不写未在事实包出现的**数字、人物言论、内部流程**；需要推断时须标明**「基于公开信息的合理推测」**并极度克制，且不与事实句混装成已定案。

本管道与 `ai-hot-news-summary`、`wechat-mp-article-writing` **分工**：前者管**检索与事实厚度**，后者管**公众号成稿去元叙事**；本文管**阶段顺序与模型分工**，**禁止**把三份 Skill 全文塞进同一条提示词让单模型「一锅炖」。

## 适用范围

| 场景 | 做法 |
|------|------|
| **Cursor / 对话 Agent** | 严格 **A→B→C**（可选 D）：事实包 → 选题与结构 JSON（`qwen3.6-plus`）→ 读者向成稿（`qwen3-max`）。 |
| **hou-cli Web** | ① 任务 **`ai_hot_news_digest`** 或 `POST /api/ai-hot-news/run` 取事实包；② 写作助手 `article_writing`，参考块贴事实包，**成稿模型选手动 Qwen3 Max**；选题/大纲可另开一轮 **Qwen3.6 Plus** 只产 JSON，再切回 Max 写正文（见「产品内落地」）。 |

受版本控制正文：**本目录 `SKILL.md` + `reference.md`**。

---

## 为何拆阶段（失败模式）

| 失败模式 | 根因 | 本管道对策 |
|----------|------|------------|
| 摘要像「行业通稿」 | 只有判断句、没有检索锚点 | 阶段 A 强制链接 + 摘录 + 每条最小信息量（见 ai-hot-news-summary） |
| 成稿像「摘要扩写」 | 把编排元语言写进正文 | 阶段 C 只遵守 wechat-mp-article-writing；禁止检索说明、交叉观察等读者不应见的节 |
| 选题空 | 一句话命题飘在天上 | 阶段 B 的 `reader_job` 必须**可执行**（见 reference 示例），不能写「建立认知」类空话 |

**模型分工**（**时间：2026-04-12**；**理由**：成本与能力档位；**方法**：）

- **选题、大纲、信源缺口、改稿意见归纳** → **`qwen3.6-plus`**（或 `bailian-qwen3.6-plus`）。
- **对外公众号长文定稿** → **`qwen3-max`**（或 `bailian-qwen3-max`）。**禁止**用 3.6 冒充终稿，除非用户**同一条消息里明文**同意。

---

## 阶段 A — 事实包（Fact Pack）

**目标**：厚、可核对；每条能支撑「读者多知道什么」；**禁止**凭记忆编造「今日」事实。

| 入口 | 操作 |
|------|------|
| **Cursor** | 执行 `ai-hot-news-summary`：先 **`date`**（如 `TZ=Asia/Shanghai date +%Y-%m-%d`）→ 多轮联网检索 → 按该 Skill 输出 Markdown。 |
| **hou-cli** | **`ai_hot_news_digest`** 或 **`POST /api/ai-hot-news/run`**；日期以返回 `meta.retrieval_date` 为准。 |

**产出物**：`fact_pack.md`（含穷尽「参考资料」），供阶段 C 嵌入叙述。**若事实包本身已出现「产业情绪」「体系化落地」类无主体句，阶段 B 须在 `source_gaps` 或 `editorial_brief` 中标记「须补锚点或删段」，阶段 C 不得扩写成更长的空话。**

---

## 阶段 B — 主编（只产 JSON + 大纲，不成稿）

**模型**：**`qwen3.6-plus`**。输出**仅供内部编排**，不是读者看到的文章。

**输入**：`fact_pack.md` + 用户约束（受众、字数、传播档/克制档、禁题）。

**输出**（**JSON 字段名固定**，示例见 `reference.md`）：

1. **`topic_sheet_v1`**  
   - `proposition_one_liner`：全文只回答**一个**可判断的问题，禁止「本周很多事」。  
   - 每个 `candidate` 的 **`reader_job`**：**禁止**「提升认知」「把握趋势」；**必须**「读完能 **\_\_\_**（一条可执行动作或一句可转述判断）」，空白处填动词短语（如「决定要不要把向量库权限接进网关日志」）。  
   - `risk_flags` / `source_gaps`：诚实标出缺链、单源、争议叙事。

2. **`outline_v1`**：`##` 级 **2～4** 条；`heading` 必须像已发公号（**事实或判断**），禁止「新闻一 / 行业观察」目录体。

3. **`editorial_brief`**：给阶段 C 的内部指令（必出现的锚点、禁词、争议分寸）。**禁止**把 brief 整段复制进正文。

**用户未选 `selected_id`**：Agent **追问一次**，或取 `priority` 最高并在 JSON 写明 `selected_id`。

---

## 阶段 C — 成稿（读者向 Markdown）

**模型**：**`qwen3-max`**。

**输入契约**（与 `article_writing_message_contract` 对齐）：

- **`【参考1：今日 AI 事实包】`**：`fact_pack.md` 全文；**不得**删掉参考资料链接后再声称可核对。  
- **`【用户本次提问】`**：写清 `selected_id`、字数、受众、是否传播档；可附 **`outline_v1` + `editorial_brief` 的短摘要**，**不要**把 `topic_sheet_v1` 全表机械贴进 user。

**输出**：**仅**公众号 Markdown（`#` + `##`…），规则以 **`wechat-mp-article-writing`** 为准：开篇即正文、无检索说明、无「交叉观察」独立大节、无 topic_sheet 字段名。

**收束自检**：成稿最后两段是否仍能让读者说出**一句带主体的事实**？若只剩「要重视生态」类句子，删掉重写收束。

---

## 阶段 D — 可选改稿

- **轻改**：删元叙事、补链接句、统一术语 → 仍以 **`qwen3-max`** 为主，或用户明示下用 3.6 只产「修改意见」，再由 Max 合并。  
- **全文重写**：须用户明示；终稿仍建议 Max。

---

## Subagent（Cursor）最小规格

System 须显式包含：

1. **A→B→C** 顺序与 **3.6 ≠ 终稿** 的硬分工。  
2. 阶段 A：**先 `date` 再搜**。  
3. 阶段 B：**只输出 JSON + outline**，不成稿。  
4. 阶段 C：**须在能调用 `qwen3-max` 的会话/编排里写**；若无 Max，**拒写定稿**并提示 hou-cli 写作助手。

---

## 产品内落地（三步）

1. 跑事实包：`ai_hot_news_digest` 或 API（见 `reference.md`）。  
2. 选题轮：临时 **Qwen3.6 Plus**，粘贴摘要，**只**要 `topic_sheet_v1` + `outline_v1` + `editorial_brief`。  
3. 写作轮：**Qwen3 Max**，参考里贴 `fact_pack`，用户句里写 `selected_id` 与成稿要求。

---

## 禁止（管道级）

- 阶段 C 用 **`qwen3.6-plus`** 冒充定稿（用户未明文同意）。  
- **无阶段 A** 直接写「今日」热点长文。  
- 成稿出现 **`检索说明` / `交叉观察` / `topic_sheet` 字段名** 等编排痕迹。  
- **把「产业情绪」「体系化」「GraphRAG 等名词」当段落核心**，而无当日素材中的具体主体与链接支撑。
- **无出处下结论**、**臆测动机或因果**、把推测写成**既成事实**。
