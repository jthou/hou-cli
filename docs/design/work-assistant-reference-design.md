# 工作助手参考块设计

## 现状

| 能力 | 工作助手 (work_assistant) | 写文章 (article_writing) |
|------|---------------------------|---------------------------|
| 参考块 | ❌ 无 | ✅ 有（按会话存储，可跨页添加） |
| 工具 | ❌ 无 | ❌ 无 |
| 上下文 | 历史对话 | 参考块 + 用户提问（不参考历史） |
| 典型场景 | 架构设计、技术选型、流程优化 | 基于参考资料写文章 |

工作助手当前**没有参考块**，仅依赖：
- 系统提示词（软件架构师角色）
- 历史对话
- 用户当前提问

## 设计目标

在「无参考块」的前提下，工作助手应如何设计？可选方向：

---

## 方案一：保持现状（轻量 Q&A）

**定位**：快速问答、头脑风暴、流程建议，不依赖外部文档。

**优点**：
- 交互简单，无额外 UI
- 适合「随口问」「快速确认」类场景
- 与写文章场景清晰区分

**缺点**：
- 无法基于需求文档、代码片段、会议纪要等作答
- 用户需手动复制粘贴到输入框，体验一般

**适用**：若工作助手主要承担「知识顾问」角色，可维持现状。

---

## 方案二：为工作助手增加参考块（推荐）

**定位**：与写文章类似，支持用户附加参考资料，但用途更广（技术方案、评审意见、测试用例等）。

### 设计要点

1. **UI 复用**：参考 ArticleWriting 的参考块面板（可收起、可新增、可编辑/预览）
2. **存储**：按会话存储，使用 IndexedDB（与写文章一致，避免 5MB 限制）
3. **提示注入**：与写文章相同格式
   ```
   以下是用户提供的参考资料，请在回答时充分利用：
   【参考1：xxx】
   内容...
   【用户本次提问】
   用户问题
   ```
4. **可选性**：参考块为可选，无参考块时行为与现状一致

### 实现路径

- 前端：WorkAssistant 增加 `referenceBlocks` 状态、参考块面板、`saveReferenceBlocks` / `loadReferenceBlocks`（可复用 `articleWritingIndexedDB` 或新建 `workAssistantIndexedDB`，按 `work_assistant` 会话隔离）
- 后端：ChatRequest 已支持 `message`，前端将参考块拼入 `message` 即可，无需改 API
- 跨页添加：可从 Wiki 阅读、网页阅读等页面「添加到工作助手」，弹出会话选择模态（与写文章一致）

### 优点

- 支持「基于这份需求写技术方案」「根据这段代码写单元测试」等场景
- 与写文章体验统一，用户学习成本低
- 实现可复用 ArticleWriting 的参考块逻辑

---

## 方案三：替代性上下文来源（不增加参考块 UI）

在不增加参考块的前提下，通过其他方式注入上下文：

| 来源 | 说明 | 复杂度 |
|------|------|--------|
| 剪贴板 | 用户粘贴后自动作为上下文 | 低 |
| 知识库检索 | 根据用户问题检索相关文档，自动注入 | 中（依赖 file_search） |
| 当前选中文本 | 从其他页面选中后「发送到工作助手」 | 中（需扩展消息传递） |

**优点**：不增加参考块 UI，交互更轻  
**缺点**：上下文来源单一，用户控制力弱，难以组合多份资料

---

## 推荐结论

- **短期**：若工作助手以轻量 Q&A 为主，可保持现状（方案一）
- **中长期**：若希望支持「基于文档/代码作答」，建议采用**方案二**，为工作助手增加参考块，复用写文章的交互与存储设计

## 与写文章的差异

| 维度 | 写文章 | 工作助手（加参考块后） |
|------|--------|------------------------|
| 系统提示 | 写作画像 + 写作规范 | 软件架构师角色 + 研发场景 |
| 工具 | 无 | 无 |
| 历史对话 | 不参考 | 参考 |
| 输出 | 文章草稿（Markdown） | 纯对话回复 |
| 参考块用途 | 写作素材、引用来源 | 需求文档、代码、会议纪要等 |

两者都支持参考块，但系统提示与输出形态不同，可共用参考块 UI 与存储逻辑。
