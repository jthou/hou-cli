# 写文章基于 MediaWiki 页面内容 - 设计方案

## 流程（四步）

1. **前端：MediaWiki 页面名**  
   写文章页上，用户能看到并维护「参考的 MediaWiki 页面」列表（页面标题）。支持通过搜索（调用现有 `GET /api/mediawiki/search`）或直接输入标题添加，支持删除。

2. **读取页面内容（已有接口）**  
   根据页面名读取正文：调用已有接口 `GET /api/mediawiki/pages/{title}` 获取对应页面内容。  
   - 若由**前端**拉取：在发送写文章请求前，前端对每个选中的页面名调该接口，拿到 content，随请求一起发给后端。  
   - 若由**后端**拉取：会话中保存当前选中的页面标题列表；后端在生成文章前，对每个标题调 MediaWiki 客户端（与上述接口同源）取 content，再拼进 prompt。

3. **AI 生成新文章**  
   输入 = 上述页面内容 + 用户在本轮聊天中的要求（及可选：当前文章草稿、写作画像等）。  
   输出 = 由 AI 生成的一篇新文章（或对当前草稿的修改/续写）。

4. **右侧预览展示生成结果**  
   将 AI 生成的文章写入当前会话的「当前文章」并返回前端；右侧预览区展示的即该内容（与现有写文章右侧预览一致，无需新增展示逻辑）。

---

## 与现有实现的关系

- **页面名**：前端需有 UI 展示/编辑「参考 MediaWiki 页面」列表（页面标题）；列表可持久在会话中（如会话级存储 `mw_source_titles`），也可每次由前端在请求里传。
- **读内容**：统一通过现有能力获取——前端用 `GET /api/mediawiki/pages/{title}`，后端用同一数据源（MediaWiki 客户端 / 对应接口的实现）按标题取 content。
- **生成与展示**：由现有写文章对话流程完成（Orchestrator 等）；把「参考页面内容」作为上下文注入当前轮的 user_prompt；生成结果写回当前文章的存储并在响应中带回，右侧预览继续用现有「当前文章」展示即可。

---

## 实施要点（精简）

| 步骤 | 做法 |
|------|------|
| 1. 前端有页面名 | 写文章页增加「参考 MediaWiki 页面」区域：展示已选标题列表，支持搜索（`/api/mediawiki/search`）添加、删除；列表可存会话（如 PUT/GET `mw-sources`）或随请求传 `mw_page_titles`。 |
| 2. 读取页面内容 | 调用已有 `GET /api/mediawiki/pages/{title}`（前端或后端均可）；若后端注入，则在构建 prompt 前对会话中的标题列表逐条拉取 content。 |
| 3. AI 生成文章 | 在现有写文章 prompt 中增加「参考 MediaWiki 页面」段落（标题 + 对应 content），与当前文章、用户输入一起交给模型，生成/修改文章。 |
| 4. 右侧预览 | 生成结果写入当前会话的 current_article，接口返回该内容；前端右侧预览沿用现有逻辑显示 current_article。 |

---

## 可选：谁负责拉取内容

- **方案 A（后端拉取）**：会话中存 `mw_source_titles`；后端在 process 时按标题调 MediaWiki 取 content，拼进 prompt。前端只维护并展示页面名列表。
- **方案 B（前端拉取）**：前端在发送前对每个标题调 `GET /api/mediawiki/pages/{title}`，将得到的 content 列表随 `POST /api/chat` 请求体传给后端（如 `mw_pages: [{ title, content }]`）；后端直接使用，无需再调 MediaWiki。

两种方式都能满足「有页面名 → 读内容（已有接口）→ AI 生成 → 右侧预览」；实现时择一即可。
