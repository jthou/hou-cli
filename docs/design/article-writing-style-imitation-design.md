# 写作助手「模仿过往文章」设计

## 目标

让 LLM 在写作助手中模仿用户曾经写过的文章风格，而非仅靠少量手动配置的范文。

---

## 方案对比：知识库 vs Skills

### Skills 不适合

| 维度 | 说明 |
|------|------|
| **定位** | Skills 是「执行特定任务」的模块（如 video_downloader、blog_writing），负责匹配用户意图并执行流程 |
| **职责** | 输入 → 执行 → 输出，不承担「存储与检索」 |
| **结论** | 范文库不是技能，不应作为 Skill 管理 |

### 知识库适合

| 维度 | 说明 |
|------|------|
| **定位** | 存储大量文档，按语义/关键词检索，按需注入上下文 |
| **职责** | 存储、索引、检索、注入 |
| **结论** | 范文库本质是「可检索的文档集合」，适合用知识库/RAG 思路 |

---

## 当前实现：写作画像 (Writing Profile)

已有能力（`config/writing_profile.json`）：

```
preferences     → 用户喜好（少用「的」、贴代码等）
style_notes    → 表述习惯（一段文字）
sample_articles → 范文列表：{ title, content } 或 { title, path }
```

- 范文通过 `get_profile_block_for_prompt()` 注入到 user 消息
- 每篇截断约 3500 字，全量注入
- **局限**：文章多时 token 爆、无语义检索、需手动维护 JSON

---

## 推荐设计：分阶段

### 阶段一：扩展写作画像（文章 < 10 篇）

**适用**：范文数量少，希望快速落地。

| 改动 | 说明 |
|------|------|
| 支持 MediaWiki 来源 | `sample_articles` 增加 `wiki_title`，运行时从 MediaWiki 拉取正文 |
| 支持目录批量导入 | `path` 支持目录，自动扫描 `.md`/`.txt` 作为范文 |
| 可选「按主题筛选」 | 用户提问含主题关键词时，仅注入相关范文（简单关键词匹配） |

**优点**：复用现有 `writing_profile`，改动小  
**缺点**：仍全量或粗筛，文章多时 token 压力大

---

### 阶段二：范文知识库（文章 ≥ 10 篇）

**适用**：范文多、希望按主题/风格精准召回。

| 组件 | 说明 |
|------|------|
| **存储** | 独立于写作画像，如 `data/writing_samples/` 或 MediaWiki 页面集合 |
| **索引** | 向量化（embedding）或关键词索引，支持按「主题 + 风格」检索 |
| **检索** | 用户提问时，检索 top-k 最相关范文片段，注入 prompt |
| **注入** | 与 `get_profile_block_for_prompt()` 类似，但内容来自检索结果 |

**与现有组件的复用**：

| 现有能力 | 复用方式 |
|----------|----------|
| `FileLongTermMemory` | 可扩展为支持「范文」类型，或新建 `WritingSampleStore` |
| `KeywordRetrievalEngine` | 关键词检索，无需向量即可用 |
| `file_search` | 可检索本地范文文件路径，但语义弱 |
| MediaWiki API | 已有 mediawiki 工具，可拉取 Wiki 页面作为范文源 |

**数据流**：

```
用户提问「写一篇关于 Python 异步编程的科普」
    ↓
检索范文库（主题：Python/异步；可选：风格标签）
    ↓
召回 2–3 篇最相关范文（或片段）
    ↓
拼入 user_prompt：写作画像 + 检索范文 + 参考块 + 用户提问
    ↓
LLM 生成
```

---

## 实现路径建议

| 阶段 | 条件 | 方案 |
|------|------|------|
| **短期** | 范文 < 10 篇 | 扩展写作画像：支持 `wiki_title`、目录 path、简单关键词筛选 |
| **中期** | 范文 10–50 篇 | 新建「范文知识库」：存储 + 关键词检索，按主题召回 |
| **长期** | 范文 50+ 篇 | 引入向量检索（embedding），支持风格/主题混合召回 |

---

## 与参考块的关系

| 来源 | 用途 | 注入时机 |
|------|------|----------|
| **写作画像** | 偏好、表述习惯、固定范文 | 每次请求 |
| **范文知识库** | 按主题/风格检索的过往文章 | 每次请求（检索后注入） |
| **参考块** | 用户本次会话手动添加的素材 | 每次请求（来自前端） |

三者可叠加：`写作画像 + 检索范文 + 参考块 + 用户提问` → 完整 user_prompt。

---

## 小结

- **Skills**：不适合，Skills 是任务执行单元，不是存储/检索载体。
- **知识库**：适合，范文多时用知识库 + 检索按需注入。
- **写作画像**：范文少时继续用，并扩展来源（Wiki、目录）和简单筛选；范文多时迁移到范文知识库。
