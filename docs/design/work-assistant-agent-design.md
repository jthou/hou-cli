# 工作助手 Agent 设计文档

## 一、概述

工作助手（Work Assistant）是一个专注于**知识工作**的 Agent，帮助用户完成工作计划、会议纪要分析、项目笔记整理、公司知识库维护等任务。项目背景与团队信息以 **MediaWiki 为唯一数据源**，Agent 在执行前读取、执行后更新相应页面。

### 1.1 定位

| 维度 | 工作助手 | 通用 Chat | 写文章 |
|------|----------|-----------|--------|
| 场景 | 计划、会议、笔记、知识库 | 通用问答、工具执行 | 写作、润色 |
| 输出 | 结构化计划、任务、知识条目 | 自由格式 | 文章、diff |
| 数据源 | MediaWiki（项目、团队、知识） | 无固定结构 | 草稿、参考 |

### 1.2 核心原则

- **MediaWiki 为唯一来源**：项目背景、团队架构、计划、会议纪要、知识库均存储在 MediaWiki
- **先读后写**：做计划、分配任务前，先读取项目背景与团队信息
- **同步更新**：任务分解与计划生成后，同步更新 MediaWiki 与看板

## 二、MediaWiki 页面结构

### 2.1 约定命名空间与页面

```
MediaWiki 页面结构（方案 A）

├── 团队/
│   ├── 组织架构          # 成员、角色、汇报关系
│   └── 角色说明          # 各角色职责与负责领域
│
├── 项目:{项目名}/
│   ├── 背景              # 项目目标、范围、约束、历史
│   ├── 目标              # 关键里程碑、截止时间
│   ├── 计划              # 当前计划（由 Agent 生成/更新）
│   └── 会议纪要/
│       └── {日期}        # 单次会议纪要及分析结果
│
└── 知识库/               # 公司知识（可选前缀）
    └── {分类}/{条目}
```

### 2.2 项目背景页面（`项目:XXX/背景`）

建议结构：

```markdown
## 项目目标与范围
- 目标描述
- 范围边界

## 关键约束
- 技术、资源、外部依赖

## 历史决策
- 重要决策及原因

## 相关链接
- 文档、资源
```

### 2.3 团队信息页面（`团队/组织架构`）

建议结构：

```markdown
## 成员列表
| 姓名 | 角色 | 负责领域 | 汇报对象 |
|------|------|----------|----------|
| 张三 | 产品 | 需求、优先级 | 李四 |
| 李四 | 技术负责人 | 架构、排期 | - |

## 角色说明
- 产品：需求、PRD、验收
- 开发：实现、代码评审
- ...
```

### 2.4 计划页面（`项目:XXX/计划`）

由 Agent 生成/更新，结构示例：

```markdown
## 阶段概览
| 阶段 | 时间 | 里程碑 |
|------|------|--------|
| 一 | 1-2周 | 需求定稿 |
| 二 | 3-4周 | 开发完成 |

## 任务分解
（与看板任务对应，可含负责人、截止时间）
```

## 三、核心能力

### 3.1 任务分解

- **输入**：用户目标、可选项目名
- **流程**：
  1. 若指定项目，用 `mediawiki` 读取 `项目:XXX/背景`、`项目:XXX/目标`
  2. LLM 分解为子任务，标注依赖、优先级、建议负责人
  3. 结合 `团队/组织架构` 匹配负责人
- **输出**：结构化任务列表（可写入计划页面、看板）

### 3.2 做计划

- **输入**：任务列表或目标描述
- **流程**：
  1. 读取项目背景与团队信息
  2. 生成阶段、里程碑、时间线
  3. 用 `mediawiki` 更新 `项目:XXX/计划`
  4. 用 `kanban_board` 创建任务、列、里程碑
- **输出**：计划摘要 + MediaWiki/看板更新结果

### 3.3 会议纪要分析

- **输入**：会议纪要文本（用户粘贴）
- **流程**：
  1. LLM 提取：决策、行动项、负责人、截止时间
  2. 用 `团队/组织架构` 校验负责人
  3. 用 `mediawiki` 创建/更新 `项目:XXX/会议纪要/{日期}`
  4. 用 `kanban_board` 创建行动项任务
- **输出**：分析摘要 + 创建的页面与任务

### 3.4 项目笔记整理

- **输入**：文件路径或目录
- **流程**：
  1. 用 `file_search`、`pdf_parser` 获取内容
  2. LLM 分类、去重、结构化
  3. 用 `mediawiki` 写入知识库或项目相关页面
  4. 可选：用 `file_organizer` 整理本地文件
- **输出**：整理结果 + 更新的页面

### 3.5 公司知识库

- **输入**：文档、问答、更新请求
- **流程**：
  1. 用 `mediawiki` 搜索、读取现有条目
  2. 用 `web_fetch`、`google_search` 补充外部信息（可选）
  3. 创建/更新 MediaWiki 页面
- **输出**：更新后的知识条目

## 四、工具配置

```python
# agent_tools_registry.py
"work_assistant": [
    "kanban_board",   # 任务、列、里程碑
    "mediawiki",      # 项目背景、团队、计划、会议纪要、知识库
    "file_search",    # 查找项目笔记、文档
    "pdf_parser",     # 解析 PDF 笔记
    "file_organizer", # 整理文件结构
    "web_fetch",      # 抓取参考材料
    "google_search",  # 补充检索
]
```

**不包含**：`whisper`（仅处理文字会议纪要）、`browser`（非核心）、`execute_code`（按需可加）

## 五、系统提示词要点

### 5.1 人设与原则

- 专注计划、会议、笔记、知识库的知识工作助手
- 以 MediaWiki 为唯一数据源，先读后写，同步更新看板
- 做计划、分配任务前必须读取项目背景与团队信息

### 5.2 上下文读取规则

1. **做计划 / 任务分解**：读取 `项目:XXX/背景`、`项目:XXX/目标`、`团队/组织架构`
2. **会议纪要分析**：读取 `团队/组织架构` 以正确分配负责人
3. **知识库维护**：先搜索相关页面，再决定创建或更新

### 5.3 输出与更新规则

1. **任务分解**：输出结构化子任务（含依赖、优先级、负责人）
2. **做计划**：更新 `项目:XXX/计划`，并在看板创建任务/里程碑
3. **会议纪要**：更新 `项目:XXX/会议纪要/{日期}`，在看板创建行动项
4. **笔记整理**：写入知识库或项目相关页面

### 5.4 缺失信息处理

- 项目背景或团队信息缺失时，先询问用户或建议创建对应页面
- 用户提供临时信息时，可先写入 MediaWiki 再继续执行

## 六、工作流程示意

```
用户：「帮我做 XX 项目的 Q1 计划」
        ↓
Agent：mediawiki get 「项目:XX/背景」「项目:XX/目标」「团队/组织架构」
        ↓
Agent：LLM 任务分解 + 排期
        ↓
Agent：mediawiki edit 「项目:XX/计划」
Agent：kanban_board create_task / create_milestone
        ↓
返回：计划摘要 + 更新结果
```

```
用户：「分析这段会议纪要：[粘贴]」
        ↓
Agent：mediawiki get 「团队/组织架构」
        ↓
Agent：LLM 提取决策、行动项、负责人
        ↓
Agent：mediawiki create 「项目:XX/会议纪要/2024-01-15」
Agent：kanban_board create_task（每个行动项）
        ↓
返回：分析摘要 + 创建的页面与任务
```

## 八、与现有 Agent 的协作

- **Orchestrator**：用户请求涉及计划、会议、笔记、知识库时，路由到 work_assistant
- **Chat**：通用对话、其他工具执行
- **Article Writing**：写作、润色、公众号

路由示例：包含「计划」「会议纪要」「笔记整理」「知识库」「任务分解」「看板」等关键词时，优先选择 work_assistant。
