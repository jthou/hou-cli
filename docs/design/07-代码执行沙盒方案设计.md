# 大模型代码执行沙盒方案设计

## 1. 需求分析

### 1.1 核心需求
- **代码生成**：大模型生成脚本代码（Python、Shell、PowerShell、Batch 等）
- **安全执行**：在隔离环境中执行代码，防止恶意操作
- **资源限制**：限制 CPU、内存、执行时间
- **结果捕获**：捕获标准输出、错误输出、执行时间等
- **脚本语言支持**：仅支持解释型脚本语言，无需编译
  - **Python**：跨平台 Python 脚本
  - **bash**：Linux/macOS Bash 脚本
  - **zsh**：Zsh 脚本（macOS 默认）
  - **PowerShell**：Windows PowerShell 脚本
  - **batch**：Windows 批处理脚本（.bat/.cmd）

### 1.2 安全要求
- **隔离性**：执行环境与主系统完全隔离
- **权限控制**：禁止访问敏感目录（/etc、/sys、/proc 等）
- **网络限制**：可配置是否允许网络访问
- **命令过滤**：白名单/黑名单机制
- **审计日志**：记录所有执行操作

### 1.3 性能要求
- **快速启动**：执行环境启动时间 < 1 秒
- **资源开销**：单个执行环境内存占用 < 100MB
- **并发支持**：支持多个代码同时执行

### 1.4 语言限制说明

**为什么只支持脚本语言？**

1. **无需编译**：脚本语言直接解释执行，无需编译步骤，执行速度快
2. **即时反馈**：大模型可以立即看到执行结果，便于迭代优化
3. **跨平台兼容**：脚本语言在不同平台都有对应的解释器
4. **安全性**：脚本语言通常比编译语言更容易进行安全限制
5. **实用性**：大模型生成的代码主要是脚本类任务（数据处理、文件操作、系统管理）

**不支持的语言类型**：
- ❌ 编译型语言（C/C++、Go、Rust、Java 等）
- ❌ 需要构建系统的语言（需要 npm install、pip install 等）
- ❌ 需要特殊运行时的语言（需要 JVM、.NET 运行时等）

**支持的语言列表**：
- ✅ **Python**：跨平台，最常用
- ✅ **bash**：Linux/macOS 系统脚本
- ✅ **zsh**：macOS 默认 Shell
- ✅ **PowerShell**：Windows 和跨平台脚本
- ✅ **batch**：Windows 批处理脚本

## 2. 方案对比

### 2.1 方案一：Docker 容器（推荐用于生产环境）

#### 优点
- ✅ **强隔离**：完全隔离的文件系统、网络、进程空间
- ✅ **易清理**：执行完成后删除容器，无残留
- ✅ **资源限制**：Docker 原生支持 CPU、内存限制
- ✅ **多脚本语言**：可预构建不同脚本语言的镜像
- ✅ **可扩展**：易于添加新语言支持

#### 缺点
- ❌ **依赖 Docker**：需要 Docker 环境
- ❌ **启动开销**：容器启动需要 0.5-2 秒
- ❌ **资源占用**：每个容器基础内存约 50-100MB

#### 适用场景
- 生产环境
- 需要强安全隔离的场景
- 多用户/多租户环境

#### 实现复杂度
- **中等**：需要 Docker API、镜像管理、容器生命周期管理

---

### 2.2 方案二：subprocess + resource 限制（推荐用于开发/测试）

#### 优点
- ✅ **轻量级**：无需额外依赖，直接使用系统调用
- ✅ **快速启动**：几乎无启动开销
- ✅ **资源限制**：使用 `resource` 模块限制内存、CPU
- ✅ **简单易用**：Python 标准库，易于调试

#### 缺点
- ❌ **隔离较弱**：共享文件系统，隔离性不如容器
- ❌ **跨平台支持**：需要处理不同平台的脚本语言差异
- ❌ **清理复杂**：需要手动管理临时文件和进程

#### 适用场景
- 开发/测试环境
- 单用户环境
- 执行脚本代码（Python、Shell 等）
- 快速原型开发

#### 实现复杂度
- **简单**：主要使用 Python 标准库

---

### 2.3 方案三：Firejail / Bubblewrap（仅 Linux）

#### 优点
- ✅ **轻量级**：比 Docker 更轻量
- ✅ **系统级隔离**：使用 Linux namespaces
- ✅ **资源限制**：支持 CPU、内存限制
- ✅ **快速启动**：启动时间 < 0.5 秒

#### 缺点
- ❌ **仅 Linux**：不支持 Windows/macOS
- ❌ **配置复杂**：需要配置 profile 文件
- ❌ **依赖系统工具**：需要安装 Firejail/Bubblewrap

#### 适用场景
- Linux 生产环境
- 需要轻量级隔离
- 不需要完整容器环境

#### 实现复杂度
- **中等**：需要配置和调用系统工具

---

### 2.4 方案四：专用沙盒服务（EvalAI、Judge0）

#### 优点
- ✅ **开箱即用**：无需自己实现
- ✅ **功能完整**：支持多种语言、资源限制
- ✅ **维护成本低**：由第三方维护

#### 缺点
- ❌ **外部依赖**：依赖第三方服务
- ❌ **可能收费**：商业服务可能收费
- ❌ **定制性差**：难以定制化
- ❌ **网络延迟**：需要网络请求

#### 适用场景
- 快速原型
- 不想维护沙盒环境
- 小规模使用

#### 实现复杂度
- **简单**：主要是 API 调用

## 3. 推荐方案：subprocess + resource（单一策略）

### 3.1 为什么选择 subprocess + resource？

**推荐理由**：
1. ✅ **无需额外依赖**：不需要 Docker、Firejail 等外部工具
2. ✅ **快速启动**：几乎无启动延迟，适合交互式场景
3. ✅ **跨平台支持**：Linux、macOS、Windows 都支持（Windows 需要特殊处理 resource）
4. ✅ **简单易用**：Python 标准库，易于调试和维护
5. ✅ **足够安全**：配合安全限制（命令过滤、路径限制、资源限制）已经足够安全
6. ✅ **资源限制**：使用 `resource` 模块可以限制内存、CPU、时间

**安全保证**：
- ✅ 命令过滤（白名单/黑名单）
- ✅ 路径限制（禁止访问敏感目录）
- ✅ 资源限制（CPU、内存、时间）
- ✅ 临时目录隔离
- ✅ 审计日志

**适用场景**：
- ✅ CLI 工具（单用户环境）
- ✅ 开发/测试环境
- ✅ 生产环境（单用户或受信任环境）
- ✅ 执行脚本语言（Python、bash、zsh、PowerShell、batch）

## 4. 详细设计

### 4.1 Subprocess 执行器设计

#### 4.1.1 资源限制

```python
import resource

def set_limits(memory_mb, cpu_seconds):
    # 内存限制（虚拟内存）
    memory_bytes = memory_mb * 1024 * 1024
    resource.setrlimit(resource.RLIMIT_AS, (memory_bytes, memory_bytes))
    
    # CPU 时间限制
    resource.setrlimit(resource.RLIMIT_CPU, (cpu_seconds, cpu_seconds))
    
    # 文件描述符限制
    resource.setrlimit(resource.RLIMIT_NOFILE, (1024, 1024))
```

#### 4.1.2 脚本语言执行

```python
# 根据语言和平台选择执行器
def get_executor_command(language: str, code: str, platform: str) -> List[str]:
    """获取执行命令"""
    if language == "python":
        return ["python3", "-c", code]  # 或写入文件后执行
    elif language == "bash":
        return ["bash", "-c", code]
    elif language == "zsh":
        return ["zsh", "-c", code]
    elif language == "powershell":
        if platform == "windows":
            return ["powershell", "-Command", code]
        else:
            return ["pwsh", "-Command", code]  # PowerShell Core
    elif language == "batch":
        # Batch 需要写入 .bat 文件
        return ["cmd", "/c", "script.bat"]
    else:
        raise ValueError(f"Unsupported language: {language}")
```

#### 4.1.3 进程隔离和临时目录管理

```python
import tempfile
import shutil
from pathlib import Path
import os
import time

class SubprocessExecutor:
    def __init__(self):
        # 创建临时工作目录
        self.temp_base = Path(tempfile.gettempdir()) / "hou-cli-sandbox"
        self.temp_base.mkdir(parents=True, exist_ok=True)
    
    def _create_work_dir(self) -> Path:
        """创建临时工作目录"""
        work_dir = self.temp_base / f"work_{os.getpid()}_{int(time.time())}"
        work_dir.mkdir(parents=True, exist_ok=True)
        return work_dir
    
    def _cleanup_work_dir(self, work_dir: Path):
        """清理工作目录"""
        try:
            shutil.rmtree(work_dir)
        except Exception:
            pass  # 忽略清理错误
```

**隔离策略**：
- ✅ **临时目录隔离**：每个执行任务使用独立的临时目录
- ✅ **路径检查**：禁止访问敏感目录（/etc、/sys、/proc 等）
- ✅ **命令过滤**：白名单/黑名单机制
- ⚠️ **注意**：subprocess 隔离性不如 Docker，但配合安全限制已足够
```

#### 4.1.4 Windows 平台特殊处理

**Windows 不支持 `resource` 模块**，需要使用其他方式限制资源：

```python
import platform

if platform.system() == "Windows":
    # Windows 使用 Job Objects 限制资源（需要额外实现）
    # 或者简化处理：主要依赖超时和命令过滤
    def set_limits(memory_mb, cpu_seconds):
        # Windows 平台简化处理
        # 主要依赖：
        # 1. 超时机制（asyncio.wait_for）
        # 2. 命令过滤（白名单/黑名单）
        # 3. 路径限制（禁止访问敏感目录）
        pass
else:
    # Linux/macOS 使用 resource 模块
    import resource
    
    def set_limits(memory_mb, cpu_seconds):
        memory_bytes = memory_mb * 1024 * 1024
        resource.setrlimit(resource.RLIMIT_AS, (memory_bytes, memory_bytes))
        resource.setrlimit(resource.RLIMIT_CPU, (cpu_seconds, cpu_seconds))
```

**Windows 平台建议**：
- 主要依赖超时机制和命令过滤
- 资源限制可以简化或使用第三方库（如 `psutil`）监控
- 重点放在命令过滤和路径限制上

LANGUAGE_MAPPING = {

            "linux": ["zsh"],

        }
    },
    "powershell": {
        "extensions": [".ps1"],
        "executors": {
            "linux": ["pwsh"],  # PowerShell Core
            "darwin": ["pwsh"],
            "windows": ["powershell", "pwsh"]
        }
    },
    "batch": {
        "extensions": [".bat", ".cmd"],

#### 4.2.2 跨平台执行策略

```python
def execute_script(code: str, language: str, platform: str) -> Dict[str, Any]:
    """执行脚本代码"""
    # 1. 验证语言支持
    if language not in LANGUAGE_MAPPING:
        raise ValueError(f"Unsupported language: {language}")
    
    # 2. 检查平台兼容性
    executors = LANGUAGE_MAPPING[language]["executors"].get(platform)
    if not executors:
        raise ValueError(f"Language {language} not supported on {platform}")
    
    # 3. 选择可用的执行器
    executor = find_available_executor(executors)
    if not executor:
        raise RuntimeError(f"No executor available for {language} on {platform}")
    
    # 4. 根据语言特性选择执行方式
    if language in ["python", "bash", "zsh"]:
        # 可以直接通过 -c 参数执行
        return execute_with_flag(executor, code)
    elif language == "powershell":
        # PowerShell 使用 -Command 参数
        return execute_with_flag(executor, code, flag="-Command")
    elif language == "batch":
        # Batch 需要写入文件
        return execute_from_file(executor, code, extension=".bat")
```

4. 检查命令是否在黑名单

```

#### 4.3.2 命令过滤示例

```python
# 白名单检查
if command[0] not in whitelist:
    raise SecurityError(f"Command not allowed: {command[0]}")

# 黑名单检查
if any(cmd in blacklist for cmd in command):
    raise SecurityError(f"Command blocked: {command}")

# 路径检查
if any(path.startswith(restricted) for path in file_paths):

```

MAX_OUTPUT_SIZE = 10 * 1024 * 1024  # 10MB

def truncate_output(output: str) -> str:
    if len(output.encode('utf-8')) > MAX_OUTPUT_SIZE:
        truncated = output[:MAX_OUTPUT_SIZE]
        return truncated + "\n... (输出已截断，超过 10MB)"
    return output
```

## 5. 安全考虑

```python

### 10.3 需要改进的地方（LangCommand 的不足）

#### 10.3.1 安全性
- ❌ **无沙盒隔离**：直接使用 `popen()` 执行命令，无隔离
- ❌ **无资源限制**：没有 CPU、内存、时间限制
- ❌ **无命令过滤**：不检查命令是否安全
- ❌ **无权限控制**：可以执行任何系统命令

#### 10.3.2 错误处理
- ⚠️ **错误处理简单**：只捕获基本异常
- ⚠️ **无超时机制**：命令可能无限执行
- ⚠️ **无资源监控**：无法知道命令的资源使用情况

### 10.4 结合建议

**借鉴 LangCommand 的优点**：
1. ✅ **输出解析**：从 LLM 输出中提取命令的逻辑
2. ✅ **实时输出**：流式处理命令执行结果
3. ✅ **交互式选择**：让用户选择和执行命令
4. ✅ **早期停止**：优化 LLM 生成效率

**结合我们的安全设计**：
1. ✅ **沙盒隔离**：在隔离环境中执行（Docker 或 subprocess + resource）
2. ✅ **资源限制**：限制 CPU、内存、时间
3. ✅ **命令过滤**：白名单/黑名单机制
4. ✅ **审计日志**：记录所有执行操作

## 11. 如何让大模型使用代码执行沙盒

### 11.1 集成方式概述

代码执行沙盒可以通过两种方式集成到大模型系统中：

1. **作为工具（Tool）**：LLM 通过 Function Calling 主动调用
2. **自动检测和提取**：从 LLM 输出中自动提取代码并执行

### 11.2 方式一：作为工具（Tool）集成

#### 11.2.1 工具定义

创建一个 `CodeExecutorTool`，继承 `Tool` 基类：

```python
from backend.core.agent.tools.base import Tool, ToolResult, ToolParameter
from backend.infrastructure.execution.secure_executor import SecureExecutor

class CodeExecutorTool(Tool):
    """代码执行工具
    
    允许 AI 助手在安全的沙盒环境中执行脚本代码。
    支持 Python、bash、zsh、PowerShell、batch 等脚本语言。
    """
    
    def __init__(self):
        parameters = [
            ToolParameter(
                name="code",
                type="string",
                description="要执行的代码内容",
                required=True
            ),
            ToolParameter(
                name="language",
                type="string",
                description="代码语言：python, bash, zsh, powershell, batch",
                required=True,
                enum=["python", "bash", "zsh", "powershell", "batch"]
            ),
            ToolParameter(
                name="timeout",
                type="integer",
                description="执行超时时间（秒），默认 30，最大 300",
                required=False,
                default=30
            ),
            ToolParameter(
                name="explanation",
                type="string",
                description="代码说明（可选），用于记录执行目的",
                required=False
            )
        ]
        
        super().__init__(
            name="execute_code",
            description=(
                "在安全的沙盒环境中执行脚本代码。"
                "\n支持的语言："
                "- python: Python 脚本（跨平台）"
                "- bash: Bash 脚本（Linux/macOS）"
                "- zsh: Zsh 脚本（macOS）"
                "- powershell: PowerShell 脚本（Windows/跨平台）"
                "- batch: Batch 脚本（Windows）"
                "\n安全限制："
                "- 代码在隔离环境中执行"
                "- 资源限制：CPU、内存、时间"
                "- 禁止访问敏感目录和危险命令"
                "\n使用场景："
                "- 数据处理和分析"
                "- 文件操作和系统管理"
                "- 数据验证和转换"
                "- 自动化任务"
                "\n注意："
                "- 仅支持脚本语言，不支持编译型语言"
                "- 代码长度限制：10KB"
                "- 输出大小限制：10MB"
            ),
            parameters=parameters
        )
        
        self.executor = SecureExecutor()
    
    def execute(self, **kwargs) -> ToolResult:
        """执行代码"""
        code = kwargs.get("code")
        language = kwargs.get("language")
        timeout = kwargs.get("timeout", 30)
        explanation = kwargs.get("explanation", "")
        
        try:
            # 执行代码
            result = await self.executor.execute_code_safely(
                code=code,
                language=language,
                timeout=timeout
            )
            
            # 构建返回结果
            return ToolResult(
                success=result["success"],
                data={
                    "output": result.get("output", ""),
                    "error": result.get("error", ""),
                    "exit_code": result.get("exit_code", 0),
                    "execution_time": result.get("execution_time", 0),
                    "memory_used": result.get("memory_used", 0),
                    "language": language,
                    "explanation": explanation
                },
                error=result.get("error") if not result["success"] else None
            )
        except Exception as e:
            return ToolResult(
                success=False,
                error=f"代码执行失败: {str(e)}"
            )
```

### 11.3 方式二：自动检测和提取（类似 LangCommand）

#### 11.3.1 设计思路

从 LLM 的输出中自动检测代码块，提取并执行：

1. **输出解析**：检测 LLM 输出中的代码块（```python、```bash 等）
2. **代码提取**：提取代码块内容
3. **自动执行**：在沙盒中执行代码
4. **结果反馈**：将执行结果追加到对话上下文

#### 11.3.2 实现架构

```python
class CodeExtractor:
    """代码提取器"""
    
    def extract_code_blocks(self, llm_output: str) -> List[Dict[str, str]]:
        """从 LLM 输出中提取代码块"""
        patterns = {
            "python": r"```python\s*([\s\S]*?)```",
            "bash": r"```bash\s*([\s\S]*?)```",
            "shell": r"```shell\s*([\s\S]*?)```",
            "sh": r"```sh\s*([\s\S]*?)```",
            "zsh": r"```zsh\s*([\s\S]*?)```",
            "powershell": r"```powershell\s*([\s\S]*?)```",
            "ps1": r"```ps1\s*([\s\S]*?)```",
            "batch": r"```batch\s*([\s\S]*?)```",
            "cmd": r"```cmd\s*([\s\S]*?)```",
        }
        
        code_blocks = []
        for language, pattern in patterns.items():
            matches = re.findall(pattern, llm_output, re.IGNORECASE)
            for match in matches:
                code = self._clean_code(match)
                if code:
                    code_blocks.append({
                        "language": self._normalize_language(language),
                        "code": code
                    })
        
        return code_blocks
    
    def _clean_code(self, code: str) -> str:
        """清理代码"""
        # 去除首尾空白
        code = code.strip()
        # 去除注释行（可选）
        # lines = [line for line in code.split('\n') 
        #          if not line.strip().startswith('#')]
        # code = '\n'.join(lines)
        return code
    
    def _normalize_language(self, lang: str) -> str:
        """标准化语言名称"""
        mapping = {
            "shell": "bash",
            "sh": "bash",
            "ps1": "powershell",
            "cmd": "batch"
        }
        return mapping.get(lang.lower(), lang.lower())


class AutoCodeExecutor:
    """自动代码执行器"""
    
    def __init__(self):
        self.extractor = CodeExtractor()
        self.executor = SecureExecutor()
    
    async def process_llm_output(
        self, 
        llm_output: str,
        auto_execute: bool = True,
        require_confirmation: bool = False
    ) -> Dict[str, Any]:
        """处理 LLM 输出，自动检测并执行代码"""
        
        # 提取代码块
        code_blocks = self.extractor.extract_code_blocks(llm_output)
        
        if not code_blocks:
            return {
                "output": llm_output,
                "code_executed": False
            }
        
        # 如果需要确认
        if require_confirmation:
            # 显示代码块，等待用户确认
            confirmed = self._prompt_confirmation(code_blocks)
            if not confirmed:
                return {
                    "output": llm_output,
                    "code_executed": False,
                    "reason": "用户取消执行"
                }
        
        # 执行代码块
        execution_results = []
        for block in code_blocks:
            try:
                result = await self.executor.execute_code_safely(
                    code=block["code"],
                    language=block["language"],
                    timeout=30
                )
                execution_results.append({
                    "language": block["language"],
                    "code": block["code"],
                    "result": result
                })
            except Exception as e:
                execution_results.append({
                    "language": block["language"],
                    "code": block["code"],
                    "error": str(e)
                })
        
        # 构建增强的输出
        enhanced_output = self._build_enhanced_output(
            llm_output, 
            execution_results
        )
        
        return {
            "output": enhanced_output,
            "code_executed": True,
            "execution_results": execution_results
        }
    
    def _build_enhanced_output(
        self, 
        original_output: str, 
        execution_results: List[Dict]
    ) -> str:
        """构建增强的输出（包含执行结果）"""
        enhanced = original_output + "\n\n"
        enhanced += "## 执行结果\n\n"
        
        for i, result in enumerate(execution_results, 1):
            enhanced += f"### 代码块 {i} ({result['language']})\n\n"
            
            if "error" in result:
                enhanced += f"❌ 执行失败: {result['error']}\n\n"
            else:
                exec_result = result["result"]
                if exec_result["success"]:
                    enhanced += f"✅ 执行成功\n\n"
                    if exec_result.get("output"):
                        enhanced += f"**输出：**\n```\n{exec_result['output']}\n```\n\n"
                else:
                    enhanced += f"❌ 执行失败\n\n"
                    if exec_result.get("error"):
                        enhanced += f"**错误：**\n```\n{exec_result['error']}\n```\n\n"
                
                enhanced += f"执行时间: {exec_result.get('execution_time', 0):.2f} 秒\n"
                enhanced += f"内存使用: {exec_result.get('memory_used', 0)} MB\n\n"
        
        return enhanced
```

### 11.4 两种方式对比

| 特性 | 方式一：工具调用 | 方式二：自动提取 |
|------|----------------|----------------|
| **主动性** | LLM 主动决定何时执行 | 自动检测和执行 |
| **精确性** | 高（LLM 明确意图） | 中（可能误检测） |
| **灵活性** | 高（可传递参数） | 低（依赖输出格式） |
| **安全性** | 高（有明确参数验证） | 中（需要额外验证） |
| **用户体验** | 需要 LLM 理解工具 | 更自然（直接生成代码） |
| **适用场景** | 复杂任务、需要参数 | 简单脚本、演示代码 |

            logger.info("Auto code executor initialized (auto extract mode)")
        except Exception as e:
            logger.warning(f"Failed to initialize auto code executor: {str(e)}")
    
    async def process_dynamic(self, task: str, context: Optional[Dict] = None) -> str:
        """处理任务（支持混合代码执行模式）"""
        # ... 准备系统提示和工具列表 ...
        
        # 获取工具列表（包含 execute_code 工具）
        tools = self.tool_registry.get_tools_for_llm() if self.code_execution_config["tool_calling"]["enabled"] else None
        
        # 调用 LLM（支持 Function Calling）
        llm_response = await self._chat_with_tools(
            system_prompt=system_prompt,
            user_prompt=task,
            tools=tools
        )
        
        # 检查是否有工具调用
        tool_calls_detected = self._has_tool_calls(llm_response)
        
        # 方式二：自动提取模式（如果启用且工具未调用）
        if (self.code_execution_config["auto_extract"]["enabled"] and 
            self.auto_code_executor and
            not (tool_calls_detected and self.code_execution_config["auto_extract"]["skip_if_tool_called"])):
            
            # 处理 LLM 输出，自动检测并执行代码
            processed = await self.auto_code_executor.process_llm_output(
                llm_response,
                auto_execute=True,
                require_confirmation=self.code_execution_config["auto_extract"]["require_confirmation"]
            )
            
            if processed["code_executed"]:
                # 如果有代码执行，将结果反馈给 LLM
                feedback_message = self._build_execution_feedback(processed["execution_results"])
                
                # 再次调用 LLM，将执行结果作为上下文
                final_response = await self._chat_with_tools(
                    system_prompt=system_prompt,
                    user_prompt=f"{task}\n\n代码执行结果：\n{feedback_message}",
                    tools=tools
                )
                return final_response
        
        return llm_response
    
    def _has_tool_calls(self, response) -> bool:
        """检查响应中是否包含工具调用"""
        # 检查响应对象中是否有 tool_calls
        if hasattr(response, 'tool_calls') and response.tool_calls:
            return True
        # 检查响应字符串中是否包含工具调用标记
        if isinstance(response, str):
            return "execute_code" in response or "tool_calls" in response
        return False
    
    def _build_execution_feedback(self, execution_results: List[Dict]) -> str:
        """构建执行结果反馈消息"""
        feedback = "代码执行完成：\n\n"
        for i, result in enumerate(execution_results, 1):
            feedback += f"代码块 {i} ({result.get('language', 'unknown')}):\n"
            if "error" in result:
                feedback += f"  ❌ 执行失败: {result['error']}\n"
            else:
                exec_result = result.get("result", {})
                if exec_result.get("success"):
                    feedback += f"  ✅ 执行成功\n"
                    if exec_result.get("output"):
                        output = exec_result["output"][:500]  # 限制长度
                        feedback += f"  输出: {output}\n"
                else:
                    feedback += f"  ❌ 执行失败: {exec_result.get('error', 'Unknown error')}\n"
            feedback += "\n"
        return feedback
```

#### 11.5.3 配置说明

**配置示例**：
```yaml
code_execution:

  tool_calling:
    enabled: true  # 启用工具调用模式

  # 方式二：自动提取模式

    require_confirmation: false  # 是否需要用户确认（false=自动执行）

    auto_extract_max_length: 5120  # 5KB（自动提取的代码更短）

#### 11.5.4 工作流程

**场景一：LLM 使用工具调用**
```
1. 用户请求 → Orchestrator
2. Orchestrator 调用 LLM（提供 execute_code 工具）
3. LLM 决定调用 execute_code 工具
4. 工具在沙盒中执行代码
5. 返回结果给 LLM
6. LLM 生成最终回复
7. 自动提取模式检测到工具已调用，跳过
```

**场景二：LLM 生成代码，自动提取执行**
```
1. 用户请求 → Orchestrator
2. Orchestrator 调用 LLM（提供 execute_code 工具）
3. LLM 直接生成包含代码块的回复（未调用工具）
4. 自动提取模式检测到代码块
5. 自动在沙盒中执行代码
6. 将执行结果反馈给 LLM
7. LLM 基于执行结果生成最终回复
```

**场景三：两种方式同时工作**
```
1. 用户请求 → Orchestrator
2. LLM 调用 execute_code 执行主要代码
3. LLM 在回复中还包含示例代码块
4. 工具调用模式：执行主要代码
5. 自动提取模式：执行示例代码（如果配置允许）
6. 合并所有执行结果
7. LLM 生成包含所有结果的最终回复
```

#### 11.5.5 优势

**同时支持两种方式的优势**：

1. **灵活性**：LLM 可以选择最适合的方式
   - 复杂任务 → 使用工具调用（更精确）
   - 简单演示 → 直接生成代码（更自然）

2. **容错性**：如果一种方式失败，另一种可以作为备选
   - 工具调用失败 → 自动提取作为备选
   - 自动提取误检测 → 工具调用作为主要方式

3. **用户体验**：满足不同使用场景
   - 需要精确控制 → 工具调用模式
   - 需要快速演示 → 自动提取模式

4. **向后兼容**：支持不同的 LLM 行为
   - 支持 Function Calling 的模型 → 使用工具调用
   - 不支持 Function Calling 的模型 → 使用自动提取

## 12. 总结

### 推荐方案
- **单一策略**：使用 SubprocessExecutor + resource 限制
- **无需 Docker**：减少依赖，快速启动
- **足够安全**：配合命令过滤、路径限制、资源限制
- **跨平台支持**：Linux、macOS、Windows（Windows 需要特殊处理）

### 关键特性
- ✅ **脚本语言支持**：仅支持解释型脚本语言，无需编译
  - Python（跨平台）
  - bash（Linux/macOS）
  - zsh（macOS）
  - PowerShell（Windows/跨平台）
  - batch（Windows）
- ✅ **强安全隔离**：Docker 或 subprocess + resource
- ✅ **资源限制**：CPU、内存、时间
- ✅ **命令过滤**：白名单/黑名单
- ✅ **跨平台支持**：自动检测平台并选择合适执行器
- ✅ **审计日志**：记录所有执行操作
- ✅ **灵活配置**：可配置执行策略和安全策略
- ✅ **混合执行模式**：同时支持工具调用和自动提取两种方式
  - 工具调用模式：LLM 主动调用 execute_code 工具
  - 自动提取模式：从 LLM 输出中自动检测并执行代码块
  - 智能协同：两种方式可以协同工作，避免重复执行

### 技术栈
- **Python 3.11+**
- **asyncio**（异步执行）
- **resource**（资源限制，Linux/macOS）
- **subprocess**（进程管理）
- **psutil**（资源监控）
- **平台检测**：根据操作系统选择执行器和限制方式
