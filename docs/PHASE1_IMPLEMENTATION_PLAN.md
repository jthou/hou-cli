# 阶段1：基础改进实施计划

## 目标

改进模型选择逻辑和工具调用优化，为后续的任务分解和并行执行打下基础。

## 任务清单

### 任务 1.1：改进模型选择逻辑

#### 1.1.1 添加任务复杂度评估

**目标**：在模型选择前评估任务复杂度，帮助选择更合适的模型。

**实施步骤**：

1. **创建任务复杂度评估器**
   - 文件：`backend/core/agent/planning/task_complexity_analyzer.py`（可能已存在，需要检查）
   - 功能：
     - 快速规则判断（关键词、任务长度等）
     - 使用推理模型进行深度分析（可选）
     - 返回 `TaskComplexity` 枚举值

2. **集成到模型选择逻辑**
   - 在 `_select_model()` 方法中调用复杂度评估
   - 根据复杂度调整模型选择策略：
     - `SIMPLE` → 优先使用对话模型
     - `MEDIUM` → 根据任务类型选择
     - `COMPLEX` → 优先使用推理模型

3. **添加缓存机制**
   - 缓存复杂度评估结果（避免重复分析）
   - 缓存模型选择结果（相同任务不重复选择）

**代码位置**：
- `backend/core/agent/orchestrator.py` 的 `_select_model()` 方法
- 可能需要创建：`backend/core/agent/planning/task_complexity_analyzer.py`

#### 1.1.2 优化快速规则判断

**目标**：改进关键词匹配逻辑，提高准确率。

**实施步骤**：

1. **扩展关键词列表**
   - 代码关键词：添加更多编程相关关键词
   - 推理关键词：添加更多推理相关关键词
   - 对话关键词：明确对话场景的关键词

2. **改进匹配逻辑**
   - 使用更智能的匹配（考虑上下文）
   - 添加关键词权重（某些关键词更重要）
   - 避免误判（如"代码"在"代码审查"中应该用推理模型）

3. **添加规则优先级**
   - 明确规则优先级顺序
   - 处理规则冲突

**代码位置**：
- `backend/core/agent/orchestrator.py` 的 `_select_model()` 方法（2568-2588行）

#### 1.1.3 优化 LLM 模型选择

**目标**：改进使用推理模型进行模型选择的逻辑。

**实施步骤**：

1. **优化提示词**
   - 更清晰的模型选择标准
   - 添加示例
   - 明确边界情况

2. **改进结果解析**
   - 更健壮的模型名称提取
   - 处理各种返回格式
   - 添加验证逻辑

3. **添加降级策略**
   - LLM 调用失败时的降级方案
   - 超时处理优化
   - 错误恢复机制

**代码位置**：
- `backend/core/agent/orchestrator.py` 的 `_select_model()` 方法（2590-2650行）

### 任务 1.2：工具调用优化

#### 1.2.1 根据工具类型选择模型

**目标**：在工具调用时，根据工具元数据选择最合适的模型。

**实施步骤**：

1. **在工具调用前选择模型**
   - 在 `_chat_with_tools()` 和 `_chat_with_tools_stream()` 中
   - 检测工具调用时，根据工具元数据选择模型
   - 使用 `tool_metadata_registry.get_recommended_model()`

2. **实现模型切换逻辑**
   - 在工具调用前切换到推荐模型
   - 工具调用后根据情况决定是否切换回原模型
   - 记录模型切换历史（用于调试）

3. **处理多工具调用**
   - 如果多个工具需要不同模型，选择最合适的模型
   - 或者为每个工具分别调用（如果支持）

**代码位置**：
- `backend/core/agent/orchestrator.py` 的 `_chat_with_tools()` 方法
- `backend/core/agent/orchestrator.py` 的 `_chat_with_tools_stream()` 方法

#### 1.2.2 增强工具参数验证

**目标**：在工具调用前进行更严格的参数验证和优化。

**实施步骤**：

1. **使用模型优化工具参数**
   - 对于需要推理的工具，使用推理模型优化参数
   - 对于代码相关工具，使用编程模型验证参数
   - 添加参数建议和修正

2. **改进参数验证逻辑**
   - 在 `ToolRegistry.execute()` 中增强验证
   - 添加类型转换和修正
   - 提供更清晰的错误信息

3. **添加参数缓存**
   - 缓存已验证的参数（避免重复验证）
   - 记录参数优化历史

**代码位置**：
- `backend/core/agent/tools/registry.py` 的 `execute()` 方法
- `backend/core/agent/tools/base.py` 的 `validate_parameters()` 方法

## 预期效果

1. **模型选择准确率提升**
   - 快速规则判断准确率 > 80%
   - LLM 模型选择准确率 > 90%

   - 复杂度评估时间 < 2秒（LLM分析）

## 风险与缓解

### 风险 1：模型选择逻辑过于复杂

**缓解**：
- 保留简单规则作为 fallback
- 添加功能开关
- 分阶段实施

### 风险 2：模型切换开销

**缓解**：
- 只在必要时切换
- 缓存模型选择结果
- 优化切换逻辑

### 风险 3：参数验证过于严格

**缓解**：
- 提供宽松和严格两种模式
- 允许跳过验证（用于测试）
- 记录验证失败但不阻止执行
