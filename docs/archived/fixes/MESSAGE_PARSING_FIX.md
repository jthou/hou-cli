# 消息解析修复说明

## 问题描述

从终端输出看到：
```
{
  "audio_path": "''.audio.mp3",
  "subtitle_path": "''.srt"
}__EVALUATION__:{"type": "evaluation", ...}
```

问题：
1. JSON内容直接显示在终端（未格式化）
2. `__EVALUATION__:` 标记在同一行，但可能没有被正确解析
3. 消息解析逻辑需要处理同一行包含多个消息的情况

## 修复内容

### 1. 改进 `parse_chunk` 方法

**文件**: `frontend/client/message_handler.py`

**改进**：
- 支持检测行中间的特殊标记（如 `__EVALUATION__:`）
- 正确分离标记之前的内容和标记之后的内容
- 改进JSON提取逻辑，支持跨行的JSON对象
- 处理JSON不完整的情况（保留在buffer中）

**关键逻辑**：
1. 检测行中是否包含特殊标记
2. 如果找到标记，分离标记前后的内容
3. 标记前的内容作为普通内容（content类型）
4. 标记后的内容提取JSON部分
5. 解析JSON并创建对应的消息类型
6. 处理剩余内容（递归）

### 2. JSON提取改进

**问题**：JSON可能跨多行，简单的字符串分割无法正确提取

**解决方案**：
- 使用括号计数法追踪JSON对象的完整性
- 考虑字符串内的转义字符
- 如果JSON不完整，保留在buffer中等待更多数据

## 测试验证

修复后，应该能够：
1. ✅ 正确解析同一行中的多个消息
2. ✅ 正确提取和解析JSON对象
3. ✅ 普通内容不会被错误解析为特殊消息
4. ✅ 特殊消息（如EVALUATION）被正确识别和渲染

## 使用建议

如果仍然看到JSON直接显示：
1. 检查后端发送的格式是否正确
2. 确认消息是否以换行符分隔
3. 查看前端日志了解解析过程
