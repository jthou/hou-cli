# 前后端交互超时优化方案

## 问题分析

### 当前问题
1. **前端超时设置**：300秒（5分钟）
2. **长时间任务**：下载视频、提取音频、生成字幕等任务可能超过5分钟
3. **缺少心跳机制**：后端在长时间运行任务时，可能长时间没有输出，导致前端认为超时
4. **自主执行器集成**：自主执行器在执行多轮对话时，可能长时间没有流式输出

### 根本原因
- 后端在长时间运行任务时，没有定期发送心跳/状态更新
- 自主执行器在执行工具调用时，可能长时间阻塞，没有输出
- 流式响应中没有定期发送状态更新

## 优化方案

### 方案1：添加定期心跳机制（推荐）

在流式响应中定期发送心跳，保持连接活跃。

**实现位置**：
- `backend/api/routes.py` - 流式响应生成器
- `backend/core/agent/planning/autonomous_executor.py` - 自主执行器

**心跳间隔**：每30秒发送一次心跳

### 方案2：添加任务进度状态更新

在长时间任务执行过程中，定期发送进度状态更新。

**实现位置**：
- `backend/core/agent/planning/autonomous_executor.py` - 自主执行器
- `backend/api/stream_sender.py` - 使用 `LongTaskMonitor`

### 方案3：增加超时配置选项

允许用户配置更长的超时时间，或根据任务复杂度动态调整。

**实现位置**：
- `frontend/client/stream_receiver.py` - 超时配置
- `env.example` - 环境变量配置

### 方案4：优化自主执行器的流式输出

在自主执行器的每个关键步骤都输出状态信息，避免长时间静默。

## 实施步骤

### 步骤1：在流式响应中添加心跳机制

在 `backend/api/routes.py` 的 `generate()` 函数中，添加定期心跳发送。

### 步骤2：在自主执行器中添加进度输出

在 `backend/core/agent/planning/autonomous_executor.py` 的 `execute()` 方法中：
- 在每轮对话开始时输出状态
- 在工具调用时输出进度
- 定期发送心跳

### 步骤3：增加超时配置

在 `env.example` 中添加：
```bash
# 流式请求超时时间（秒）
# 默认：300（5分钟）
# 对于长时间任务（如下载视频、生成字幕），可以设置为更大的值
STREAM_TIMEOUT=600
```

### 步骤4：优化工具执行时的输出

在工具执行过程中，定期输出进度信息，避免长时间静默。

## 预期效果

1. ✅ 长时间任务不会因为超时而中断
2. ✅ 前端能够实时看到任务进度
3. ✅ 连接保持活跃，不会超时
4. ✅ 用户体验更好，知道任务正在执行
