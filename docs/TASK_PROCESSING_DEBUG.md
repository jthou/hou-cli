# 任务处理流程调试改进

## 问题描述

用户反馈任务没有开始执行。为了帮助诊断问题，我们在任务处理流程的关键步骤添加了详细的调试信息。

## 改进内容

### 1. 复杂度分析阶段调试信息

在 `stream_process` 方法中，复杂度分析之前添加了调试信息：

```python
# 发送调试信息：开始复杂度分析
debug_info = {
    "type": "debug",
    "category": "planning",
    "message": "开始分析任务复杂度",
    "details": {}
}
yield StreamMessageBuilder.build_debug(debug_info)
```

同时添加了异常处理，确保复杂度分析失败不会阻塞任务执行：

```python
try:
    if self.complexity_analyzer.use_llm:
        is_complex = await self.complexity_analyzer.is_complex_task_async(task, history)
    else:
        is_complex = self.complexity_analyzer.is_complex_task(task, history)
except Exception as e:
    logger.warning(f"复杂度分析失败: {str(e)}", exc_info=True)
    # 分析失败时，默认不创建规划文件，继续执行
    is_complex = False
```

### 2. 工具调用流程调试信息

在工具调用流程的各个阶段添加了调试信息：

- **未匹配到技能时**：发送"未匹配到技能，使用工具处理"消息
- **准备工具时**：显示工具列表和数量
- **模型选择时**：显示"开始模型选择"和"模型选择完成"消息
- **开始LLM调用时**：发送"开始调用LLM进行工具选择"消息

### 3. 调试信息输出顺序

现在任务处理流程会按以下顺序输出调试信息：

1. ✅ "开始流式处理任务"
2. ✅ "创建新会话"（如果需要）
3. ✅ "获取历史消息"
4. ✅ "开始分析任务复杂度"（如果启用规划功能）
5. ✅ "检测到复杂任务，已创建规划文件"（如果是复杂任务）
6. ✅ "技能匹配"（如果匹配到技能）
7. ✅ "未匹配到技能，使用工具处理"（如果没有匹配到技能）
8. ✅ "准备工具"
9. ✅ "开始模型选择"
10. ✅ "模型选择"
11. ✅ "开始调用LLM进行工具选择"
12. ✅ "工具调用循环第 X 轮"
13. ✅ "检测到工具调用"
14. ✅ "执行工具"

## 如何查看调试信息

### 在前端查看

调试信息会以 `__DEBUG__:` 格式发送到前端，前端应该解析并显示这些消息。

### 在日志中查看

所有调试信息也会记录到日志中，可以通过以下方式查看：

```bash
# 查看实时日志
tail -f logs/app.log | grep "DEBUG\|INFO"

# 查看特定会话的日志
grep "session_id" logs/app.log
```

## 常见问题诊断

### 问题1：任务完全没有开始

**可能原因**：
- 流式处理没有正确启动
- 前端没有正确接收消息
- 网络连接问题

**诊断步骤**：
1. 检查是否收到"开始流式处理任务"消息
2. 检查网络连接
3. 查看后端日志是否有错误

### 问题2：任务卡在复杂度分析

**可能原因**：
- LLM调用超时（如果使用LLM辅助判断）
- 复杂度分析器异常

**诊断步骤**：
1. 检查是否收到"开始分析任务复杂度"消息
2. 检查是否收到后续消息
3. 查看日志中的异常信息

**解决方案**：
- 设置 `PLANNING_USE_LLM=false` 使用基于规则的判断
- 检查LLM服务是否正常

### 问题3：任务卡在工具调用

**可能原因**：
- LLM调用超时
- 工具执行失败
- 工具调用循环达到最大次数

**诊断步骤**：
1. 检查是否收到"开始调用LLM进行工具选择"消息
2. 检查是否收到"工具调用循环第 X 轮"消息
3. 查看工具执行结果

## 环境变量配置

为了确保任务处理正常，建议设置以下环境变量：

```bash
# 规划功能
export ENABLE_PLANNING=true
export PLANNING_COMPLEXITY_THRESHOLD=0.2
export PLANNING_MIN_TASK_LENGTH=10
export PLANNING_USE_LLM=false  # 如果LLM调用有问题，设置为false

# LLM服务
export DEEPSEEK_API_KEY=your_api_key
```

## 测试建议

1. **简单任务测试**：发送一个简单的任务，检查是否能正常处理
2. **复杂任务测试**：发送一个复杂任务，检查规划文件是否创建
3. **工具调用测试**：发送需要工具调用的任务，检查工具是否被正确调用
4. **技能匹配测试**：发送匹配技能的任务，检查技能是否被正确执行
