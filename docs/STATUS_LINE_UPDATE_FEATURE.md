# 状态行同一行更新功能

## 功能说明

对于长任务（如下载视频、生成字幕等），后端会定期发送状态更新。前端在同一行实时显示这些状态信息，而不是每次都创建新的行，提供更清晰的用户体验。

## 实现方式

### 后端

后端通过 SSE（Server-Sent Events）发送状态更新消息，格式为：

```json
{
  "type": "status",
  "data": {
    "task": "处理中",
    "message": "任务正在执行中...",
    "elapsed_time": 30.5
  }
}
```

### 前端

前端使用 Rich 库的 `Live` 组件来实时更新显示。当收到 `status` 类型的消息时：

1. **构建状态行**：将状态信息格式化为一行文本
   - 任务名称（如果有）
   - 状态消息
   - 已用时间（如果有）

2. **同一行更新**：将状态行追加到内容下方，使用 `Live` 组件的 `update` 方法实时更新

3. **自动换行**：当收到普通内容（`content` 类型）时，自动结束状态行并换行

## 显示效果

### 状态行格式

```
处理中 | 任务正在执行中... | ⏱️ 2分30秒
```

### 更新流程

1. **初始状态**：
   ```
   [计划] 任务分析完成，制定了 3 个执行步骤。
   
   处理中 | 任务正在执行中... | ⏱️ 0秒
   ```

2. **状态更新**：
   ```
   [计划] 任务分析完成，制定了 3 个执行步骤。
   
   处理中 | 正在下载视频... | ⏱️ 30秒
   ```

3. **内容输出**（自动换行）：
   ```
   [计划] 任务分析完成，制定了 3 个执行步骤。
   
   [工具调用] 正在执行: video_downloader
   [工具结果] video_downloader 执行成功
   ```

## 代码实现

### 前端修改

**文件**: `frontend/ui/stream_handler.py`

**关键修改**:

1. 添加 `current_status_line` 属性用于跟踪当前状态行
2. 在 `render_stream` 方法中：
   - 维护 `status_display` 变量
   - 收到 `status` 消息时，构建简单的状态行并更新 `Live` 组件
   - 收到 `content` 消息时，结束状态行并换行

### 后端修改

后端无需修改，继续使用现有的状态更新机制。

## 优势

1. **节省屏幕空间**：状态信息在同一行更新，不会产生大量重复的状态行
2. **实时反馈**：用户可以实时看到任务状态
3. **清晰易读**：状态信息简洁明了
4. **自动管理**：当有实际内容输出时，自动结束状态行，不会干扰内容显示

## 使用示例

### 测试任务

```bash
export BACKEND_PORT=6080
export ENABLE_AUTONOMOUS_EXECUTION=true
export STREAM_TIMEOUT=600
python -m frontend.main chat "下载视频 https://www.bilibili.com/video/BV1jMqgBEERW?t=0.5 ，并从音频中提取字幕"
```

### 预期输出

```
[计划] 任务分析完成，制定了 3 个执行步骤。

处理中 | 任务正在执行中... | ⏱️ 5秒
处理中 | 正在下载视频... | ⏱️ 30秒
处理中 | 正在提取音频... | ⏱️ 1分15秒
处理中 | 正在生成字幕... | ⏱️ 2分30秒

[工具调用] 正在执行: video_downloader
[工具结果] video_downloader 执行成功

[工具调用] 正在执行: ffmpeg
[工具结果] ffmpeg 执行成功

[工具调用] 正在执行: whisper
[工具结果] whisper 执行成功

✅ 任务完成！
```

## 注意事项

1. **状态行长度**：状态行可能会很长，如果终端宽度不够，Rich 库会自动处理溢出
2. **刷新频率**：`Live` 组件的刷新频率设置为 10 次/秒，确保状态更新流畅
3. **兼容性**：如果终端不支持 `Live` 组件，会降级到普通输出模式
